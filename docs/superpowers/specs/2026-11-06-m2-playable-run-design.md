# M2 — หนึ่งรอบที่เล่นจบได้ (Knight ครบ + XP + เลเวลอัป + HUD) — Design

- วันที่: 2026-11-06
- สถานะ: ร่างรอรีวิว
- ต่อจาก: `docs/superpowers/specs/2026-10-30-m1-core-systems-design.md` (M1 ปิดแล้ว gate ผ่านบน M3)
- ตัวเลข gameplay เป็นของ `docs/design.md` เอกสารนี้เสนอตัวเลขใหม่เฉพาะที่ design.md ยังไม่ระบุ (หัวข้อ 5.3) และต้องเพิ่มลง design.md ก่อนเขียนโค้ด

## 1. เป้าหมาย

ทำให้เกมเล่นจบได้หนึ่งรอบด้วย Knight: **Camp → Run → Results → กลับ Camp** ผู้เล่นฆ่าศัตรู เก็บ XP เลเวลอัป เลือกการ์ด ตาย แล้วเห็นสรุปผลและยอด Embers

ขอบเขตที่ตกลงกับผู้ใช้ (2026-11-06):

- **รวม Shield Bash และ Warhorn ใน M2** ชื่อ milestone ใน design.md คือ "Knight ครบ" และตารางอาวุธระบุว่า Knight มีสองชิ้นนี้ แต่ roadmap เดิมไม่มีงานให้ จึงเพิ่มเป็น M2-22 ขึ้นไป
- **อาวุธคุยกับ EnemySystem ผ่าน API ตรง** (หัวข้อ 3.3) ไม่ใช้คิวเหตุการณ์ชน ไม่ใช้ Area2D
- ไม่ทำใน M2: Ranger, Pyromancer, พาสซีฟจากการ์ด (M3), Elite, กล่องเสบียง, evolution, บอส (M4), ร้านอัปเกรดและเซฟลงดิสก์ (M4), ปุ่มหนีกลางรอบ

## 2. เงื่อนไขผ่าน

| ข้อ | เกณฑ์ |

| XP | ศัตรูตายทิ้ง gem ผู้เล่นเดินเข้าใกล้แล้วถูกดูด เก็บแล้ว XP ขึ้น เก็บก้อนใหญ่ทีเดียวขึ้นหลายเลเวลได้และแสดงการ์ดต่อเนื่อง |

## 3. สถาปัตยกรรม

### 3.1 หน้าจอและสถานะ

```
main.tscn (Node2D, main.gd)        state machine: CAMP → RUN → RESULTS → CAMP
├─ camp_screen.tscn                ปุ่มเริ่มคืน + ยอด Embers
├─ run.tscn  (Node2D, run.gd)      เจ้าของลำดับการอัปเดตของหนึ่งรอบ
│  ├─ EnemySystem (MultiMeshInstance2D)
│  ├─ PickupSystem (MultiMeshInstance2D)      XP gem
│  ├─ Player (CharacterBody2D) + Camera2D
│  ├─ FxLayer (Node2D)                         ภาพฟัน/กรวย/คลื่น วาดด้วย _draw()
│  ├─ HUD, LevelUpPanel, PauseScreen (CanvasLayer)
│  └─ DebugOverlay
└─ results_screen.tscn             สรุปผล + ปุ่มกลับ Camp
```

- `main.gd` สลับหน้าโดย `queue_free()` ฉากเก่าแล้วสร้างฉากใหม่ ไม่เก็บอะไรของรอบเก่าไว้ สิ่งเดียวที่ข้ามหน้าได้คือ `RunSummary` (Run → Results) และ `embers_total` ที่ main ถือไว้**ในหน่วยความจำเท่านั้น** (หายเมื่อรีโหลดหน้า เซฟจริงเป็นของ M4 `SaveService`)
- Run มี 4 สถานะ: `RUNNING`, `LEVEL_UP`, `PAUSED`, `ENDED` เฉพาะ `RUNNING` ที่เรียก `step()` เมื่อไม่ได้อยู่ใน RUNNING ทุกระบบหยุดนิ่ง รวมถึงเวลาของรอบและบัฟ

### 3.2 ลำดับการอัปเดตต่อเฟรม

`run.gd` เรียกตามลำดับนี้ (ระบบลูกยังไม่มี `_physics_process`):

| # | ขั้น | หมายเหตุ |
|---|---|---|
| 1 | `player.tick` | เดิน จับเวลาอมตะ |
| 2 | `spawner.tick` | |
| 3 | `enemies.tick_grid` | |
| 4 | **`loadout.tick`** | อาวุธนับคูลดาวน์และยิง query กริดที่เพิ่งสร้าง ส่งดาเมจ/ผลัก/มึนงง ศัตรูที่ตายตรงนี้ทิ้ง gem |
| 5 | `enemies.tick_separation` | |
| 6 | `enemies.tick_contact` | |
| 7 | `enemies.tick_movement` | บวกความเร็ว knockback ที่ลดลง และข้ามการไล่ของตัวที่มึนงง |
| 8 | **`pickups.tick`** | ดูดและเก็บ gem → `RunState.add_xp` |
| 9 | `enemies.sync_multimesh`, `pickups.sync_multimesh`, `fx.tick` | |

อาวุธต้องอยู่หลังสร้างกริดและก่อนศัตรูขยับ ตามกฎเดิมของ M1 ศัตรูที่ถูกฆ่าหลังสร้างกริดยังค้างในกริดจนเฟรมถัดไป ทุกที่ที่อ่านกริดต้องเช็ค `is_alive` (เหมือน `tick_contact`)

### 3.3 อาวุธคุยกับศัตรูอย่างไร

`EnemySystem` เพิ่ม API สาธารณะ ทุกตัวคืนค่าพื้นฐานหรือเติม buffer ที่ผู้เรียกส่งมา ไม่ส่ง Packed array ออก (กฎ copy-on-write):

| เมธอด | หน้าที่ |
|---|---|
| `query_radius(center, r, out) -> int` | เติม id ของศัตรูที่มีชีวิตในรัศมีลง `out` คืนจำนวน |
| `damage(id, amount) -> bool` | ลด HP คืน true ถ้าตายครั้งนี้ (ตายแล้วเรียก `kill` เอง) |
| `knockback(id, direction, distance)` | ผลักออกรวม `distance` px ส่งเป็นความเร็วที่ลดลงเป็นศูนย์ใน `knockback_duration` |
| `stun(id, seconds)` | ตั้งเวลามึนงง ตัวที่มึนงงไม่ไล่ผู้เล่นแต่ยังถูกผลักได้ ติดซ้ำรีเซ็ตเวลา ไม่ซ้อน |

อาวุธแต่ละชิ้นทดสอบรูปร่างเอง (มุมและระยะ) บนรายชื่อที่ได้ แล้วเรียกผ่าน `WeaponContext.deal_damage(id, amount, weapon)` ซึ่งเป็น**จุดเดียว**ที่: คูณดาเมจด้วยตัวคูณชั่วคราวของผู้เล่น, เรียก `enemies.damage`, บันทึกดาเมจต่ออาวุธลง `RunState`, และคำนวณดูดเลือด Oathguard (เฉพาะอาวุธแท็ก STEEL)

อาวุธยิงตามคูลดาวน์เสมอแม้ไม่มีศัตรูในระยะ (เห็นการฟันตลอด) ค่าใช้จ่ายคือ query กริดหนึ่งครั้งต่อการยิง

### 4.1 วงจรของหนึ่งรอบ

1. ศัตรูตาย → `enemy_died(pos, xp)` → `PickupSystem` วาง gem (ช่องเต็ม → ให้ XP ทันที)
2. gem อยู่ในรัศมีเก็บของผู้เล่น → ถูกดูดด้วยความเร็วคงที่ → แตะตัว → `RunState.add_xp`
3. XP ล้นเกินเกณฑ์ → ขึ้นเลเวลหลายครั้งต่อเนื่อง แต่ละครั้งเข้าคิว
4. คิวไม่ว่าง → Run เข้า `LEVEL_UP` → `LevelUpPanel` แสดงการ์ดใบแรกของคิว → ผู้เล่นเลือก → `card_picked` → Run นำไปใช้ (เพิ่ม/อัปอาวุธ หรือใช้การ์ดสำรอง) → แสดงใบถัดไป หมดคิวแล้วกลับ `RUNNING`
5. ผู้เล่นตาย → Run สร้าง `RunSummary` → main เปลี่ยนไป Results และบวก Embers เข้า `embers_total` → ปุ่มกลับ Camp

### 4.2 การ์ดเลเวลอัป

พูลของ Knight ใน M2 คือ Greatsword, Shield Bash, Warhorn (ไม่มีพาสซีฟจากการ์ดจน M3) กติกาตาม design.md หัวข้อ 9: เสนอของที่ถืออยู่และยังไม่ LV5 กับของใหม่ถ้ายังมีช่องอาวุธว่าง ของที่ถืออยู่น้ำหนัก ×2 เลือก 3 ใบไม่ซ้ำ ถ้าตัวเลือกจริงไม่ครบ 3 ใบ เติมด้วยการ์ดสำรอง Hearth Bread (ฮีล 30) และ Ember Purse (+5 Embers ตอนจบรอบ) การสุ่มใช้ `Rng` ของ Run (seed เดียวกันได้ผลเดียวกัน) ต้องเพิ่ม `Rng.weighted_pick()` ที่เลื่อนมาจาก M1 (M1-3)

## 5. ข้อมูล

### 5.1 Schema ใหม่ (`data/`)

- `WeaponDef`: `id`, `display_name`, `tag` (STEEL/HOLY), `class_id` (ว่าง = อาวุธกลาง), `levels: Array[WeaponLevelDef]` (5 แถว)
- `WeaponLevelDef`: `cooldown`, `damage`, `arc_degrees`, `range`, `radius`, `knockback`, `stun_seconds`, `both_sides`, `buff_percent`, `buff_seconds`, `heal` ช่องที่อาวุธนั้นไม่ใช้ = 0
- `CardDef`: ชนิด (อาวุธ / สำรอง), `weapon`, `heal_amount`, `embers_bonus` สำหรับการ์ดสำรอง
- `ClassDef` เพิ่ม: `start_weapon`, `class_weapons`, `steel_lifesteal`
- `RunTuning` เพิ่ม: `xp_base` 5, `xp_per_level` 4.5, `embers_kills_divisor` 10, `embers_seconds_divisor` 15, `knockback_duration` 0.2, `gem_pull_speed` 180, `gem_capacity` 512, `gem_radius` 3

### 5.2 ตัวเลขอาวุธ (ตรงตาราง design.md หัวข้อ 5)

| อาวุธ | LV1 | LV2 | LV3 | LV4 | LV5 |
|---|---|---|---|---|---|
| Greatsword (STEEL) | 140° ระยะ 48 ดาเมจ 20 cd 1.1 ผลัก 20 | ดาเมจ 25 | 180° ระยะ 56 | cd 0.9 | ฟันหน้าและหลัง |
| Shield Bash (STEEL) | 90° ระยะ 40 ดาเมจ 8 cd 3 ผลัก 60 มึนงง 0.5 | ดาเมจ 12 | ดาเมจ 16 มึนงง 1 | ดาเมจ 20 | ดาเมจ 24 cd 2 |
| Warhorn (HOLY) | รัศมี 70 ผลัก 30 บัฟ +15% 3 วิ cd 6 | รัศมี 80 | รัศมี 90 | รัศมี 100 บัฟ +25% | รัศมี 110 ฮีล 10 |

เลเวลสูงสะสมค่าของเลเวลก่อนหน้า (LV5 ของ Greatsword มี 180° ระยะ 56 cd 0.9 ดาเมจ 25) Warhorn ไม่มีดาเมจ บัฟคือตัวคูณดาเมจ**ทุกอาวุธ**ของผู้เล่น ยิงซ้ำเพียงรีเซ็ตเวลา ไม่ซ้อน

### 5.3 ตัวเลขที่ design.md ยังไม่มี (ต้องเพิ่มก่อนเขียนโค้ด)

- **หน่วยผลัก:** "ผลัก N" = ระยะ N px ที่ศัตรูถูกผลักออกทั้งหมด ส่งเป็นความเร็วที่ลดเป็นศูนย์ใน 0.2 วิ ดังนั้นความเร็วเริ่มต้น = `2N / 0.2`
- **XP gem:** ดูดด้วยความเร็ว 180 px/s เมื่ออยู่ในรัศมีเก็บ (เร็วกว่าทุกอาชีพ) เก็บเมื่อแตะตัว ช่องมี 512 อัน ถ้าเต็มให้ XP ทันทีโดยไม่วาง gem
- **เลเวล:** ไม่มีเพดาน เริ่มที่เลเวล 1 เกณฑ์ไปเลเวลถัดไป `round(5 + lv × 4.5)` (lv1 → 10 XP)
- **การเติมการ์ด:** ถ้ามีตัวเลือกจริงน้อยกว่า 3 ใบ เติมการ์ดสำรอง (หัวข้อ 4.2)

## 6. การทดสอบ

**GUT (ทุกข้อที่ไม่ผูกกับภาพ):**
- `RunState`: XP curve, XP ล้นข้ามหลายเลเวล, คิวเลเวลอัป, ช่องบิลด์เต็ม, สูตร Embers (รวม Ember Purse), ดาเมจต่ออาวุธ
- `LevelUpDeck`: 3 ใบไม่ซ้ำ, น้ำหนัก ×2 ของที่ถืออยู่ (สถิติจาก seed คงที่), ไม่เสนออาวุธที่ LV5, เฉพาะอาวุธของอาชีพตัวเอง, เติมการ์ดสำรองเมื่อไม่พอ, ซ้ำได้ด้วย seed เดียวกัน
- `EnemySystem`: `query_radius` ไม่คืนตัวที่ตาย, `damage` ฆ่าเมื่อ HP หมดและยิง `enemy_died` ครั้งเดียว, `knockback` ระยะรวมตรงตามค่าและผลักแล้วกลับมาไล่ต่อ, `stun` ติดซ้ำรีเซ็ตและตัวที่มึนงงไม่ไล่
- อาวุธ: เรขาคณิตของฟัน/กรวย/วงกลมที่ขอบมุมและขอบระยะ, ตารางเลเวล 1–5 ตรง design, คูลดาวน์, ศัตรูตัวเดียวไม่โดนซ้ำในการฟันเดียวตอน LV5, Shield Bash ใส่มึนงงตามเลเวล, บัฟ Warhorn ไม่ซ้อนและหมดเวลา, ดูดเลือดเฉพาะแท็ก STEEL
- `PickupSystem`: ดูดเฉพาะในรัศมี, เก็บแล้ว XP ถูก, ช่องเต็มให้ XP ทันที, slot ถูกคืนหลังเก็บ
- `Main`: Camp → Run → Results → Camp ไม่มีสถานะรอบเก่าค้าง (รอบสองเริ่มที่เวลา 0 เลเวล 1 ไม่มีศัตรูเดิม)

**ด้วยตาและ overlay (ตาม checklist ท้าย design.md):** เล่นจริงหนึ่งรอบครบวงจร, กด F4 พร้อมอาวุธ 3 ชิ้นแล้วอ่าน ms ต่อขั้น, ภาพฟัน/กรวย/คลื่นอ่านออก, การ์ดเลือกด้วยคีย์ 1/2/3 และคลิก

## 7. การตัดสินใจและสิ่งที่แลกไป

- **API ตรงแทนคิวเหตุการณ์:** เรียบง่ายและตรงกับรูปแบบของ M1 แลกกับการ query กริดหนึ่งครั้งต่อการยิงของแต่ละอาวุธ ถ้า M3 มีอาวุธหลายชิ้นจนรู้สึกหนักค่อยพิจารณารวมการ query
- **StatBlock ขนาดเล็กก่อน:** เก็บแค่ตัวคูณดาเมจชั่วคราวและดูดเลือดเพื่อให้ Warhorn กับ Oathguard ทำงาน ตัวเต็มของ M3-1 จะรวมชั้นอื่นเข้ามา ข้อเสียคือต้องย้ายเมื่อถึง M3
- **Embers ในหน่วยความจำ:** ไม่ทำเซฟล่วงหน้า (M4) จึงหายเมื่อรีโหลด ยอมรับได้เพราะ M2 ยังไม่มีอะไรให้ซื้อ
- **ไม่มีปุ่มหนีกลางรอบ:** design.md บอกว่ากดหนีไม่ได้ Embers จึงไม่ต้องมีเส้นทางพิเศษ M2 จบรอบได้ทางเดียวคือตาย
- **อาวุธยิงแม้ไม่มีเป้า:** เห็นการโจมตีตลอดและเทสต์ง่าย แลกกับ query ที่อาจว่างเปล่า
- **การ์ดสำรองเติมช่อง:** พูลของ Knight มีแค่ 3 ชิ้นจนถึง M3 ผู้เล่นจะเจอการ์ดสำรองบ่อยหลังอาวุธครบ LV5 นี่คือพฤติกรรมที่ตั้งใจใน M2

## 8. ความเสี่ยงและถ้าประสิทธิภาพเกิน

- แกนเสี่ยงคือ **separation บนเว็บกิน ~5 ms** (วัดใน M1-15) การเพิ่มอาวุธและ pickup จะบวกเข้าไป ถ้า ms รวมต่อก้าว physics บนเว็บใกล้ 16 ms ให้ทำ M1-16 (แบ่ง separation เป็นหลายเฟรม ปรับ `cell_size`) ก่อนเดินหน้า
- เอฟเฟกต์ภาพวาดด้วย `_draw()` ต้องไม่ allocate ต่อเฟรม ถ้าช้าให้ลดจำนวนช่อง หรือย้ายไป MultiMesh
- ตัวเลขใหม่ในหัวข้อ 5.3 ยังไม่เคย playtest เป็นค่าตั้งต้นสำหรับปรับจูนทั้งหมด
